# Booking AI — статус реализации

## Как запустить
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r req.txt
cp .env.example .env          # заполните DATABASE_URL, JWT_SECRET, при желании ADMIN_EMAIL/ADMIN_PASSWORD
alembic upgrade head          # создаёт таблицы
python -m mysite.seed         # страны, города, категории, первый администратор
uvicorn main:app --reload     # Swagger: http://127.0.0.1:8000/docs
pytest                        # тесты не требуют сети, токенов и Ollama (SQLite in-memory, HTTP замокан)
```

### ИИ-ассистент и Telegram (этап 3)
```bash
ollama pull llama3.2           # модель из OLLAMA_MODEL (по умолчанию llama3.2:latest)
# в .env: OLLAMA_URL=http://127.0.0.1:11434 (или OLLAMA_BASE_URL), OLLAMA_MODEL=llama3.2:latest
# в .env: TELEGRAM_BOT_TOKEN=<токен от @BotFather>, TELEGRAM_BOT_USERNAME=<имя бота без @>
alembic upgrade head           # добавляет таблицу ai_channel_link_codes (миграция 0002)
uvicorn main:app --reload      # чат: POST /api/v1/ai/chat
python -m mysite.integrations.telegram_poll   # бот через long polling (отдельный процесс)
```
Привязка Telegram к аккаунту: `POST /api/v1/channels/telegram/link` (с JWT) → отправить боту `/start КОД`.
Без привязки бот умеет только поиск; создание/изменение/удаление и подписки требуют привязанного аккаунта.
**Токен бота храните только в `.env`** (он в `.gitignore`); если токен попал в переписку или репозиторий,
перевыпустите его в @BotFather (`/revoke`).

## Сделано
- **Этап 0 (из прошлой сессии):** модели БД, модерация, валидация, граф LangGraph.
  Восстановлены файлы, которых не было в присланном архиве: `schemas/search.py`, `graph/state.py`,
  `data/blocked_words.txt`, `.env.example` (`settings_ai.py` заменён единым `mysite/config.py`).
- **Исправлено в графе:** при постоянном checkpointer `response` и `confirmed` «залипали» между сообщениями
  (подтверждение удаления действовало бы на следующие запросы диалога). Теперь они сбрасываются.
- **Этап 2:**
  - `config.py`, `database/session.py` (ленивый async-движок), `services/security.py` (bcrypt, JWT).
  - Авторизация: регистрация (роль всегда `user`), логин, одинаковый ответ на неверный email/пароль, отключённые пользователи не входят.
  - CRUD: страны, города (имя уникально в пределах страны), категории (дерево, защита от циклов), объявления,
    подписки, уведомления (чтение), запрещённые слова (админ, с обновлением модерации «на лету»), пользователи.
  - Справочники нельзя удалить, пока они используются (409), вместо этого — `is_active=false`.
  - Объявления: статусы draft → active → inactive, владелец/админ, чужие черновики скрыты (404),
    валидация + модерация при создании, правке и публикации, дубликаты (409), `country_id` берётся по городу.
  - Поиск `POST /api/v1/search/` по локальной БД (категория с вложенными, страна, город, цена, комнаты, гости, площадь).
  - Alembic (async) + baseline-миграция из metadata моделей; сид справочников.

- **Этап 3 (код написан, не запускался):**
  - `clients/ollama.py`: классификатор через `/api/chat` с JSON-схемой (`format`), температура 0, плоская схема
    ответа для маленькой модели, один повтор при мусоре, затем `unknown`; недоступность Ollama → `OllamaUnavailable` (503).
  - `services/ai_chat.py`: граф запускается в рабочем потоке, обращения к БД возвращаются в цикл событий;
    названия категорий/городов из речи превращаются в id; все права и проверки — прежние сервисы.
  - Подтверждение удаления хранится на сервере по ключу «канал + пользователь + диалог» с TTL (`AI_PENDING_TTL_SECONDS`);
    клиент не может передать `confirmed` сам. «Да» не уходит в LLM.
  - Граф: данные прошлого сообщения переносятся, только если прошлый ход закончился уточнением того же намерения
    (раньше фильтры старого запроса «прилипали» к новому); для `create` обязателен `title`.
  - `POST /api/v1/ai/chat` (токен необязателен: без него только поиск), `/api/v1/channels/*` (привязка Telegram).
  - Telegram: клиент Bot API, long polling и webhook (`/api/v1/telegram/webhook`, секрет в заголовке), только личные чаты,
    дедупликация через `ProcessedMessage`, одноразовый код привязки (15 минут, таблица `ai_channel_link_codes`),
    токен не попадает в логи и тексты ошибок (INFO-логи httpx отключены).
  - `OLLAMA_URL` принимается как синоним `OLLAMA_BASE_URL`.
- Состояние диалога графа (MemorySaver) и ожидающие подтверждения лежат в памяти процесса: после перезапуска или
  при нескольких воркерах теряются. Для продакшена нужен Postgres-checkpointer и хранение ожидания в БД/Redis.
- Telegram-бот и API — отдельные процессы, диалоги у них не общие.
- **WhatsApp** по-прежнему не сделан (этап 6): нужен официальный Cloud API (токены Meta). Через личный номер — нарушение правил WhatsApp.
- **Этап 4:** `SearchProvider` (Tavily), извлечение данных, robots.txt, `/api/v1/search/history`.
- **Этап 6:** WhatsApp (подпись webhook, дедупликация, привязка `ChannelAccount`); Telegram уже сделан в этапе 3.
- **Этап 7:** периодическая проверка подписок, `Notification`, повторы отправки.
- **Этап 8:** Docker Compose, интеграционные тесты на PostgreSQL/Ollama, документация.
- Ограничение частоты запросов (rate limiting) на API, логин, `/ai/chat` и Telegram: без него анонимный `/ai/chat` можно использовать для нагрузки на Ollama.

## Известные особенности
- Сравнение названий города/страны без учёта регистра работает на PostgreSQL; в SQLite `lower()` не понижает кириллицу.
- Baseline-миграция вызывает `metadata.create_all`; дальнейшие изменения — через `alembic revision --autogenerate`.
